Djehuti Math

Engineering mathematics with FRust, worksheets, and AI assistance.

Your first calculation

  1. Open the Worksheet tab. The starting document contains notes and an executable FRust cell.
  2. Press Run cell. The embedded compiler generates native code and runs it on the application worker.
  3. Open Variables: answer should be 42.
  4. Edit, add notes or FRust cells, and use File → Save Worksheet. Files use the versioned .djmath format.

Shared scalar workspace

Worksheet cells and the full FRust editor share a workspace. A missing scalar returns NaN. This initial workspace supports finite real scalar values.

pub fn run() -> String = {
    let resistance: f64 = 1000.0;
    let current: f64 = 0.012;
    math_set_scalar("voltage", resistance * current);
    "Voltage calculated"
}

Editor and execution

Use View → FRust for the full source editor with dark syntax highlighting, compile diagnostics, Run and Stop. File can open and save standalone FRust sources. One program executes at a time. Compiled FRust runs with this user's local process permissions; it is not a sandbox.

BYOK agent

Use Settings → Agent Settings to select a profile and enter an OpenAI API key and model. Keys are protected with Windows user-scoped DPAPI in Djehuti Math's own storage. No key is copied from another application. The provider currently exposed is OpenAI.

The agent retrieves relevant LiteSemRAG reference cards for each request and can inspect or edit worksheet cells, run FRust, inspect actual execution results and variables, apply layouts, and open Help. Your requests and the retrieved reference context are sent to the selected provider. A request to run a program returns a start acknowledgement; execution status contains the actual result. Cancellation ends further agent actions; an in-flight network request may finish in the background.

Node programming

View → Node Designer is the graphical editor for FRust. Drag nodes from the palette, wire output pins to input pins, set literals in the inspector, and use Validate, Compile (shows the generated FRust), Export .fr and Compile & Run. Nodes compile to real FRust source; there is no separate interpreter. Breakpoints and watches on nodes are used by Debug, which drives the Debugger panel (Continue, Pause, Step Into/Over/Out, stack, variables). Programs save as .frnode.json. The Layout menu has a Node Programming preset.

Audio effects (DSP)

View → DSP Effects (or Layout → Audio DSP). An effect is FRust that defines process_sample(audio_in, ws, coeffs) and declares its controls with comment directives:

// @effect Soft Clip
// @param drive "Drive" 1 20 4 x
// @param level "Level" 0 1 0.7
// @workspace 1
pub fn process_sample(audio_in: f64, ws: Array<f64, 1>, coeffs: Array<f64, 3>) -> f64 = {
    djehuti_dsp_tanh(audio_in * coeffs[0]) * coeffs[1]
}

ws is persistent state per channel, coeffs holds the declared parameters in order followed by the sample rate. Host math functions available to effects: exp, log, sin, cos, tan, tanh, atan, sqrt, pow (djehuti_dsp_*). Pick a template, Compile (native x64 code, built off the UI thread), adjust the parameter sliders, then Render Test a sine, noise, impulse or sweep and read peak, RMS, DC, clipping and harmonic levels, Play Render, or Save WAV. Start Live runs the effect between the audio input (hardware or a looping audio file) and the output; the audio device opens only when you ask (Audio Settings or Start Live).

VST3 export

Export VST3 packages the compiled effect into a Windows x64 VST3 bundle: the precompiled Djehuti Math Effect runtime plus the effect in Contents/Resources/effect.frust-il. The plugin links the native code when loaded; no compiler runs in the host. Parameters, bypass, input/output gain and dry/wet mix are automatable. Limitation: every export shares the runtime's compiled VST3 class identity, so a host cannot tell two different exports apart by class. The effect contract is the target of the future Math-to-FRust compiler.

Agents and external tools

The built-in agent and an optional local API use the same tools as the buttons: FRust check/run, node programs and debugging, DSP effects, audio and VST3 export. While Djehuti Math runs it listens on 127.0.0.1 only; the port and a bearer token are in %APPDATA%\DjehutiMathgent-api.json. GET /v1/tools lists the tools and POST /v1/tools/call runs one. Anything that can read that file as your user can call these tools, including the file-writing ones.

Layouts and recovery

The Layout menu offers Default, Focused Worksheet, FRust Development, Node Programming, Audio DSP, and named user layouts. Panel tabs can be docked, floated, and closed. The current layout is saved automatically. Default is used when no valid state exists. Worksheet contents are recovered on an ordinary close, separately from your saved worksheet file. Runtime variables and outputs are recalculated in each application session.
